Thanks for the clean review. All three functionality notes were real behavior, so they're taken along with the polish.

**Optional items:**
- **`sio::LoadString`:** gone. The assembler now prunes a component's optional entry points by reference, so an unused one no longer ships. The component's version is also renamed `LoadStringSetting`, so it no longer collides with the Win32 `LoadString` macro in the mods that do use it. `ReadStringSetting`/`CopyStringSetting` remain this mod's one string reader.
- **Stale `RetryLoop` comment:** it now says that `Start()` may run on Windhawk's thread and the taskbar thread at once, and that the exchange handles it.
- For consistency with the family, `no_destroy` on `g_retry` is removed and the global is marked `exit-time-safe: heap-only`. Our audit now requires that shape for a `RetryLoop` instead of the attribute. That reverses what I said last round.

**Functionality notes:**
- **"No placements yet" is settled, and now watched.** You're right that `NaturalWidth`'s floor means it can only be a written arrangement (with `NewItems = ignore`) that names no utility Windows is showing. That exit now retires the retry and leaves a **watch-only** drift check registered on the tray. That check records every candidate host's icon count and the number of candidate hosts, and re-runs the layout when either changes. So the named utility is placed when it appears, not at the next settings change or rebuild. `RestoreLayout` revokes the watcher and drops the tray reference, as before.
- **Lone-icon `MainStack` fallback:** a single visible icon is adopted as `emoji` only when it matches no other utility's token. With the emoji panel hidden and the touch keyboard left alone in `MainStack`, the keyboard keeps its own slot.
- **Microphone/location churn:** unmanaged candidate counts now leave out the in-use indicator glyphs (the six the privacy indicators use). A call starting or ending no longer schedules a restore and re-apply. I did not restrict the count to utility-*matching* glyphs, because the lone-icon emoji fallback exists precisely for an emoji panel whose glyph isn't recognised.

The rebuild hook and the settings-change path both used `forceFirstAttempt`. They now use the loop's new `StartOrWake()`, whose first attempt always runs even while `LayoutIsApplied()` still truthfully reports the old tree. On the rebuild path it also wakes a live run instead of stopping and waiting for it on the taskbar thread.
