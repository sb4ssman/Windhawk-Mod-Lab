Thanks. The blocking item was real, and following it turned up a second freeze on the same path.

**Correction first.** Last round's reply said `igc::Acquire` was removed. It was not. The mod is assembled from shared components, and that overload lived in one the mod uses. The assembler now prunes a component's optional entry points by reference. I checked this push file: `Acquire` (renamed `AcquireAtAnchor` in the component), `sio::LoadString` and `forceFirstAttempt` are not in it.

**1. The StartTaskbar hook blocking on the icon worker.** Both parts of your suggestion are taken:
- **The hook no longer waits.** It calls the shared `RetryLoop`'s new `StartOrWake()`. A live run is woken (it skips its interval and gets a fresh budget) rather than stopped and restarted, and a new run is started only when none is live. Only Windhawk's thread (unload, settings change) ever waits for the worker.
- **The probe is interruptible and bounded.** `PrepareFolderIcons` checks `RetryLoop::StopRequested()` between entries as well as `g_unloading`. A target whose extraction fails *slowly* (1 s or more, the unreachable-share case) is remembered and not probed again until the settings are reloaded. Fast failures are not remembered, because at Explorer start the Shell may simply not be ready yet.

**The second freeze.** `PrepareFolderIcons` held `g_folderIconsMutex` for the whole extraction, and `NativeFolderIcon` takes that mutex on the UI thread while building a grid. So even with the hook fixed, a build could wait out the same SMB timeout. The mutex now guards only the cache and the failed-target list. The Shell calls run with no lock held (`ExtractFolderIcon`), and the result is inserted afterwards. The folder README now says that a slow-failing target keeps its label until the next settings change.

**Optional items, all taken:**
- **Dead code and stale comments:** `igc::Acquire`, `sio::LoadString` and `forceFirstAttempt` are gone, as above. `BuildFolderButtonGrid` now calls `ngl::RowsInHeight` instead of repeating its formula inline. `g_injectedSlot` is removed along with its five writes. The comments carried over from the tray-utility mod are now generic in the shared component. The `GetSystemMetricsForDpi` comment no longer describes a dynamic lookup the code doesn't do. The `RetryLoop` comment says what is true about its callers.
- **`no_destroy` on `g_retry`:** removed, and marked `exit-time-safe: heap-only`. The lab's exit-time audit now rejects `no_destroy` on a `RetryLoop`.
- **Includes:** `<cmath>` added. `Windows.UI.Xaml.Input.h` and its `using namespace` are removed. `Controls.Primitives.h` stays: `Button::Click` is declared on `ButtonBase`, and removing it fails the build.
- **`g_menuIdleEvent` leak** on the `HookTaskbarDllSymbols` failure path: the event is now closed before `Wh_ModInit` returns `FALSE`.

**Functionality note, taken:** the `LayoutUpdated` handler now calls `PositionAfterAppIcons` only when one of five cheap reads has changed since the last placement: the repeater's child count and `ActualWidth`, the frame's width and height, and the tray's width (the tray is right-aligned, so its left edge moves with it).
