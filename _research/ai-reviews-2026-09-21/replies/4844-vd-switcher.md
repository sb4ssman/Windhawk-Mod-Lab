Thanks. The blocking item was real, and so was the correction on the dead code.

**Correction first.** Last round's reply said `sio::LoadString`, `ContentAlong`, the uncached `Measure`/`Arrange` and `ResolveArrangement` were removed. They were not, and you were right to call it out. The mod is assembled from shared components, and those functions sat inside components the mod does use. The assembler now prunes optional entry points: a component marks them, and one ships only when the mod's own code, or other shipped component code, references it. I checked this push file against your list: none of them are in the file, and neither is `<climits>`.

**1. `OnTaskbarRebuilt` and the stale grid.** Fixed as you suggested. `TrayUI::StartTaskbar` now marks a reapply pending and wakes the retry instead of applying once. The retry's first attempt runs `RemoveButtonGrid()`, which finds no bar in the new tree. It revokes the old buttons' handlers, drops their records, clears the Start-overlay globals and their `LayoutUpdated` token, and nulls `g_buttonGrid`. Then it rebuilds. Once the old bar is gone the pending flag is cleared, so if the new tray isn't reachable yet, the next attempt simply applies. The leak of one grid's `ButtonEventState` records per rebuild is gone with it.

The hook runs on the taskbar thread inside Explorer's own taskbar construction, so it does not use `Start()`, which stops the previous run and waits for it. The shared `RetryLoop` gained `StartOrWake()`. It wakes a live run, which then skips its interval and gets a fresh budget. It starts a new run only when none is live, so it never waits. The `RetryLoop` comment about "both callers on the UI thread" now says what is true: `Start()` may run on Windhawk's thread and the taskbar thread at once, and the exchange handles it.

**Optional items, all taken:**
- **`no_destroy` on `g_retry`:** removed. It now carries the same `exit-time-safe: heap-only` marker as the other heap-only globals, and the lab's exit-time audit now rejects `no_destroy` on a `RetryLoop` so this can't come back.
- **`LoadSettings()` racing UI-thread readers:** settings now load inside the UI-thread dispatch in `Wh_ModSettingsChanged`. If the taskbar thread exists but that dispatch doesn't run, the load is deferred to the retry's UI-thread attempt. Only when there is no taskbar thread at all, so no reader exists, does it load on Windhawk's thread.
- **Unclamped integers:** `FontSize` is clamped to at least 1, and `CornerRadius` and `BorderThickness` to at least 0, at load.
- **`position` default** now matches the declared default, `afterClock`.

**Functionality notes, both taken:**
- **Preview text DPI:** captions and footer now use the shell's message font at the popup's DPI (`SystemParametersInfoForDpi` + `CreateFontIndirectW`). It is created per paint like the brushes, with the stock font as the fallback.
- **`GetWindowTextW` on a hung same-process window:** for windows owned by Explorer itself, the caption is read with `SendMessageTimeoutW(WM_GETTEXT, SMTO_ABORTIFHUNG | SMTO_BLOCK, 100 ms)`. An aborted read gives an untitled thumbnail. Other processes' windows still use `GetWindowTextW`, which never blocks for them.
