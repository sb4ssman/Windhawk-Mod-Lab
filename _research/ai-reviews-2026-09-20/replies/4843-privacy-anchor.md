Thanks — both blocking items were real, and item 1 was the worst bug this mod could have. Addressed in this push:

**1. Hidden with nothing in its place.** Suppression is now a single decision, `ApplyNativeSuppression`, made on every path (initial track, glyph change, visibility change). A native indicator is collapsed only when the anchor bar is live **and** has a slot for that indicator's type (`Both` needs the location and microphone slots). Otherwise anything the mod wrote on it is handed back through the lease. That covers all three routes you listed:
- The `Loaded` path only tracks icons when `g_syntheticGrid` exists after the injection attempt, so a failed, stood-down or empty injection leaves the icon alone.
- With all four `Content` toggles off, `ApplyStyle` returns before `ScanMainStack`.
- With one toggle off, that device's native glyph is tracked but never collapsed. The README now says so.

As suggested, the type is no longer guessed. An empty glyph is tracked with `typeKnown = false`: it sets no active flag and is never suppressed, and the decision is made in the text callback once the glyph arrives. `UntrackPrivacyElement` only clears a flag that a known type set. That also resolves the "guessed `Location`" functionality note. An already-tracked icon is re-evaluated when `ApplyPrivacyIndicatorBehavior` sees it again, so an icon tracked before the bar appeared is suppressed once the bar exists.

One detail worth noting: restoring writes `Visibility`, which raises that icon's visibility callback synchronously while `RestoreObject` is still iterating its snapshots. A re-entrancy guard makes the nested call a no-op.

**2. Vertical stand-down bypassed.** The check is now `TaskbarRequiresStandDown()`, called at the top of `InjectSyntheticIcons`, so every injection path honours it. `ApplyOnTaskbarThread` clears `g_taskbarRestarted` before standing down and calls `RemoveModUi()` if anything is already injected. That makes the stand-down complete in both directions (your functionality note).

**Optional items taken:**
- Dropped `NonActivatableStack` from the host-stack filter. For the record, it was added last round on the previous review's advice, but you're right that the scan only walks `MainStack`, and the two should agree.
- Removed the unleased `iconView.IsHitTestVisible(true)`.
- `g_uiHostWnd` is now set where injection succeeds, in `InjectSyntheticIcons`.
- Removed the redundant `catch { Release; throw; }` around `PlaceChild`.
- The glow tree is only built when `Surface.GlowEnabled` is on.
- `g_taskbarWnd` and `g_uiHostWnd` are `std::atomic<HWND>`, loaded once per use. The state worker's double read, a null check followed by a use, could see a rebuild in between.
- `g_settings` is loaded into a copy on Windhawk's thread and published on the taskbar thread. If that dispatch never runs, it is published directly, so a change is never lost.
- `g_startLease` is a `std::optional` reset on the UI thread, like its neighbours.
- AppModel-driven Copilot re-checks are coalesced to one per 2 s.
- The unused template surface is gone. The mod is now assembled from ten small components (6383 → ~6040 lines), with its own focused tree walk instead of the shared one. `tbh::RetryLoop`, `sio::StringSetting`, `vtw::*`, `ple::Lease::{Abandon,Count,Empty}` and `start_placement::Side::Over` no longer exist in the file.

**Not changed, with reasons:**
- **`-loleaut32` is required.** `LogCurrentUiException` calls `winrt::hresult_error::message()`, and C++/WinRT stores that message in a `BSTR`. Removing the flag fails the link with undefined `SysStringLen` and `SysFreeString`. We tried it on 2026-09-19.
- **`OpenSettingsForItem` stays on the UI thread.** Moving `ShellExecuteW` to a worker would need a thread that `Wh_ModUninit` joins, or the launch could still be running in this image after unload. It runs only on a user's tap and hands an `ms-settings:` URI to the protocol broker, so we judged the extra lifecycle surface not worth it.
- **`auto` rows on a 48 px taskbar:** deliberate, and the README was what was wrong. Two 16 px rows do fit a standard taskbar, and the live-tested gallery shot of the 2×2 block was taken on one. The README now says that `auto` gives 2×2 on a standard taskbar and shows the single-row expression beside the single-row screenshot.
- **Overlap with tray-utility-customizer:** each mod leases its own named tray slot and restores only that slot on unload. They group different things (utilities vs privacy indicators), so a user who wants both gets two deliberate slots rather than a conflict.
