Thanks for the careful trace — both blocking items were real, and item 2 is why we removed the bridge rather than patching it.

**1 + 2. The 1.7 bridge is removed.** `HasLegacySettings`, `PreferCurrentOrLegacy*` and `Behavior.UseLegacySettings` are gone. Your item 2 is the root problem, and neither of the two fixes you offered removes it:
- Windhawk has no API to write a setting. `Wh_SetIntValue`/`Wh_SetStringValue` are mod storage and invisible to the settings page. So any bridge, including "until first save" or a storage snapshot, leaves a stretch where the settings page shows one value and the bar uses another.
- The "default means unset" rule makes a carried value impossible to set back to its default (your `beforeClock` → `afterClock` example).
- The mapping gaps in item 1 (`"dot"`, `gridVerticalOffset` → `PadY`, the Task View keys) showed that a partial bridge produces *wrong* results. A wrong migration is worse for a user than an obvious one-time reset.

The README's "Upgrading from 1.x" section, which you noted contradicted the bridge, is now accurate again. It says settings reset once on update, and now also tells users to copy their settings in Textual mode first. This also makes your "please test Save with undeclared keys" question moot.

**Optional items taken:**
- **Dead template code:** the mod is now assembled from eight small components, with its own focused tree walk (5,432 → 5,119 lines). Gone from the file: `property_lease`, `ContentAlong`/`AvailableRows`/`PixelsToDip`/`ResolveArrangement`/uncached `Measure`/`Arrange`, `vtw::*`, `sio::LoadString`/`sio::StringSetting` (now `WindhawkUtils::StringSetting`), `GetWindowsAccentBrush` and `VdPositionName`, along with the commentary about other mods and lab files.
- **Retry:** it now **uses** `RetryLoop`; the hand-rolled `CreateThread` worker is gone.
- **Deferred settings reapply freezing the bar:** fixed as you suggested. A reapply that could not run sets `g_reapplyPending`. While it is set, each retry attempt removes and rebuilds the old bar rather than treating "a grid exists" as done. The notification thread is restarted meanwhile, so the old bar keeps following desktop switches.
- **`RunFromWindowThread` running a callback once per concurrent hook:** fixed in the shared dispatch component with a `ran` flag in `Dispatch`, so every mod built from it gets the fix.
- **`!tornDown` branch:** the code now matches the rationale. Handler records hold strong XAML references, so they are retained with the other owners rather than cleared from Windhawk's thread. The preview window class is unregistered from the current thread when the popup's own thread can't be reached (it fails harmlessly if a window still exists).
- **`s_reapplied`:** replaced by a small struct passed through the `void*`. `InvalidateButtonGridSizeEstimate()` now runs on the UI thread, next to `RemoveButtonGrid()`.
- **Small stuff:** duplicate includes and `<thread>` removed; `<dwmapi.h>`/`<shobjidl.h>` moved to the top; the "NEW in v2.1" comment rewritten; the init log uses `WH_MOD_VERSION`. The embedded README's lab-relative link now points at the repository, and our README sync tooling does that for every lab link from now on.

**Functionality notes:**
- **Previews on secondary taskbars:** fixed. The hosting taskbar is now whichever of this process's taskbars contains the cursor (the hover that scheduled the preview is over the button), instead of a XamlRoot match that only works on the primary taskbar.
- **Untitled windows** are now drawn and counted, just without a caption. **Past the 48-window cap**, the extra windows are still counted in the footer. **`DWM_TNP_SOURCECLIENTAREAONLY`** is no longer set: `rcSource` is computed from the window rect, and the frame-included default is what we want.
- **Left as is:** the per-hover `CoCreateInstance` and registry reads. They run once per hover after the 400 ms delay, and caching a COM object in a namespace-scope holder would add a thread-affine release to unload. We also kept the 100 ms cursor poll while the popup is up. `PointerExited` covers the normal exit, but the poll is the backstop when the pointer leaves through the popup, which is `HTTRANSPARENT`, or when the button is rebuilt underneath it.
