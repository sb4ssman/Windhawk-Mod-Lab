Thanks — all four were real. Addressed in this push:

**1(a). Unload no longer gives up.** The `attempt < 50` cap is gone. Uninit loops `EndMenu` + `WM_CANCELMODE` until the menu path is idle, exactly as you suggested. Each `RunFromWindowThread` is a `SendMessage`, so the loop follows the taskbar thread's real progress. The give-up branch, the "retaining the idle event" leak, and the conditional `CloseHandle` are all gone.

**1(b). The queued Shell verb is now inside the wait.** There is a shared RAII `MenuPathScope` that owns the `fetch_add`/`ResetEvent` … `fetch_sub`/`SetEvent` pairing. `ShowFolderMenu` holds it for its whole tail, and `MenuOwnerSubclassProc` holds it around `InvokePendingShellCommand`. A Delete confirmation or Open With dialog now keeps unload waiting until it is answered.

Following the same reasoning turned up one more window, now closed. Both sites read `g_unloading` *before* opening their scope. Uninit could store the flag and read a depth of zero in between. Then `TrackPopupMenu`'s loop would pump uninit's own cleanup dispatch and return into a freed image. Both sites now open the scope first and check `g_unloading` after it. Uninit stores the flag before reading the depth, so with seq_cst atomics one side always sees the other.

**2. Native icons on a running Explorer / on settings change.** We took your simpler option. `Wh_ModAfterInit` and `Wh_ModSettingsChanged` no longer apply directly; the worker's first attempt (no delay) runs `PrepareFolderIcons()` before the first build. This also removes the label→icon flash.

**3. `LoadLegacyFolders`.** Removed, together with the whole 0.7 bridge (`HasLegacySettings`, `PreferCurrentOrLegacy*`, `Behavior.UseLegacySettings`). Windhawk has no API to write a setting, so a bridge always leaves the settings page showing a value the mod isn't using. The "prefer legacy while the 2.0 value equals its default" rule also meant a carried value could never be set back to its default (your functionality note and the clamp note both describe symptoms of this). The README now says plainly that settings reset once on update, and how to copy them across.

**4. README.** The `|` in the Arrangement table is escaped. "Upgrading from 0.7" describes the one-time reset and the 150-item default. The `ShowHidden` row says hidden-only.
