Thanks — the `g_stoodDown` regression was real. Addressed in this push:

**1. Transient states no longer retire the retry.** `g_stoodDown` is now set only for decisions another attempt cannot change: a vertical taskbar, every utility switched off, or a *measured* tray below `MinimumTrayHeight`. The three transient exits return `false` and keep the bounded retry alive:
- a tray with `ActualHeight() <= 0` (not arranged yet);
- no layout items yet;
- no placements yet.

The budget is now 20 attempts × 1.5 s, because "not populated yet" is now what the loop is waiting out.

Beyond the retry budget, as you suggested, each apply now records the visible-icon count of every *unmanaged* candidate host as a weak reference. The `LayoutUpdated` check compares those as well as the managed hosts, so a `MainStack` that fills in after a chevron-only apply re-runs the layout. To keep the added walk off the hot path, the check is throttled to 500 ms instead of 250 ms.

**Optional items:**
- **`RetryLoop::Start` re-entry:** already fixed. `run_` is published by `std::exchange` under the mutex, and whatever it displaces is stopped. This is the shape you proposed.
- **`no_destroy` on `g_retry`:** you're right that it guards no wait, and the comment now says so. The attribute stays because our exit-time-destructor audit requires every namespace-scope object with a non-trivial destructor to be either marked or proven heap-only. Removing it fails that check.
- **Dead code:** `FindDirectTrayHost` and the `FindCurrentProcessTaskbarWnd` wrapper are removed. `RestoreObject` and the two `Metrics` fields belong to components shared with sibling mods, where they are used; splitting the components per function would cost more than those few lines.
- **`Wh_ModSettingsChanged` without a taskbar** now loads the settings, so the next `StartTaskbar` rebuild uses them.
- **`Wh_ModAfterInit`** starts the same bounded retry instead of making a single attempt.
- **`AcquireAt` with a stale marker:** fixed in the shared lease component. A same-named marker that is *not* the caller's live lease is released and the slot is taken fresh, with the requested slot corrected if the released marker sat before it. The caller's own live lease is still refused, because acquiring twice would strand the first slot.

**Functionality notes:**
- **The 1.x fallback** is removed entirely, along with `Behavior.Use1xFallback`, the legacy nudges and the expression transpose. You identified the core problem: Windhawk stores defaults at install, so the bridge can't tell a default from a choice, and it can't be undone from the settings page. The same applies to the `minimumTrayHeight = 0` case. Because Windhawk has no API to write settings, any bridge leaves the UI showing one value while the mod uses another. The README now says settings reset once on update and how to carry them across.
- **Restore order on a Grid tray:** the host marker is now inserted at the host's live index on both panel kinds, and the host is re-inserted at the marker's index on both. Child order is therefore exact after a disable/re-enable, including keyboard/UIA order.
- **Drift-check cost:** the throttle is raised to 500 ms, as described above.
