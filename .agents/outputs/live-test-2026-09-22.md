# Live test — all six mods, round 5/6 review fixes (2026-09-22)

Build: the lab working tree after the round-5/6 review work. Every mod is
`SUBMISSION_PREFLIGHT_OK`. Install each lab `.wh.cpp` over the installed copy.
No settings reset this time: no setting keys changed.

Shared-code changes that touch several mods at once:
- Retry loop: an Explorer taskbar rebuild now WAKES the running retry instead
  of stopping it and waiting (VD, OmniButton, Folder Menus, Tray Utility).
- The unused-code pruning changes what ships, not behavior. The compiler has
  checked it; the live test confirms nothing that was used got pruned.

The single most useful test for this round is an **Explorer taskbar rebuild
while the mods are running**. Two reliable ways: change the display scaling
(Settings → Display → Scale) and back, or unplug/replug a monitor. Restarting
Explorer is NOT the same test; it reloads the mods from scratch.

## 1. VD Switcher (had the blocking item)

1. With the bar showing, trigger a taskbar rebuild (above): the bar comes back
   within a few seconds, without switching desktops. This was the bug.
2. Same in a Start position (Left of Start): bar returns, Start and the task
   buttons are not left shifted.
3. Switch desktops a few times after the rebuild: highlight follows; hover
   previews still work.
4. Preview on a high-DPI monitor (150%+ if you have one): title and footer
   text are readable size now, not tiny.
5. Hover a desktop whose File Explorer window is showing a slow/unreachable
   network path: the taskbar does not freeze.
6. Set Font size to 0 and Corner radius to -3: the bar still shows (clamped),
   rather than vanishing.
7. Change a few settings (label format, colors): applied immediately.

## 2. OmniButton (had the blocking item)

1. Normal use: arrangement as before, battery percentage updates.
2. Taskbar rebuild (scaling change): OmniButton re-applies.
3. If you have the vertical taskbar mod: enable it while OmniButton is running:
   OmniButton hands the native button back rather than re-arranging it.
   (Skip if you don't have that mod.)
4. Watch the Windhawk log for a few seconds of idle: no repeating
   "Native OmniButton items changed - re-applying" lines.

## 3. Taskbar Folder Menus (had the blocking item)

1. Normal use: buttons, native icons, menus as before.
2. Add a folder entry pointing at an unreachable share (e.g. `\\nosuchhost\x`)
   with "Use native Shell icon" on. Then trigger a taskbar rebuild: the taskbar
   stays responsive (it used to freeze for the network timeout). That entry
   shows its label; the log says it will not be probed again.
3. Change any setting: the unreachable entry is probed once more (expected).
4. Placement "after app icons": opening/closing apps still re-places the group.

## 4. Tray Utility Customizer

1. Normal use, then a taskbar rebuild: layout re-applies.
2. Hide the emoji panel so only the touch keyboard is in the tray area: the
   keyboard keeps its own slot (no empty gap).
3. Start and end a call or voice recording (microphone indicator): the log
   should NOT show a layout re-apply each time.
4. Optional edge case: Arrangement = `touchKeyboard`, New items = ignore, with
   the touch keyboard icon hidden. Then show the touch keyboard icon: it is
   placed within about a second (used to need a settings change).

## 5. Privacy Indicator Anchor

1. Normal use with the camera/mic in use: bar and native indicators behave as
   before.
2. With the mic in use (native mic indicator suppressed), disable the mod: the
   native indicator comes back correctly.

## 6. Clock Spacer

1. Normal use: spacing as before.
2. In Taskbar Clock Customization, hide a line whose format contains `%s%`: it
   stays hidden (it used to come back as spaced rows).
3. Change Max clock width here: applied on the next tick.
4. Disable the mod: clean, no half-second pause.
